# 项目池统计定时同步需求

## 1. 背景

项目池列表中的“交付逾期”“工单逾期”“未完成工单”和“目前环节”来自 `ops_project_pool_snapshot` 快照；点击统计标签后的工单弹框直接查询 `tickets` 表。两处数据刷新时机不同，可能出现列表仍显示数量、弹框已经没有工单的情况。

## 2. 目标

- 工单变化不再触发项目池快照即时刷新。
- 由服务端定时任务统一刷新项目池快照和 Redis 缓存。
- 策划、环节、项目等页面分组继续使用现有前端汇总逻辑，不新增重复统计表。
- 不改变提单、工单状态流转、权限和弹框筛选功能。

## 3. 统计口径

定时任务刷新每个有效项目及其版本的项目池行：

- 交付逾期：当前阶段交付时间早于当前时间。
- 工单逾期：工单状态不是“已完成”，且工单交付截止时间 `due_at` 早于当前时间。
- 未完成工单：工单状态不是“已完成”。
- 目前环节：未完成工单按 `segment_id` 聚合。

预警时间 `warn_at` 只用于“预警/临期”类逻辑，不作为“工单逾期”的判断条件。

## 4. 同步方式

- 服务启动后延迟执行一次全量快照刷新。
- 默认每 5 分钟刷新一次，可通过环境变量调整。
- 每次刷新使用现有 `rebuildProjectPoolSnapshots()`，写入 `ops_project_pool_snapshot`，并重建项目池 Redis 缓存。
- 单次刷新未完成时跳过下一轮，避免并发重建。
- 定时任务异常只记录日志，不影响 HTTP 服务和工单操作。

## 5. 影响范围

- 工单创建、改派、状态修改：保留原有工单写入、通知和流转记录，取消即时项目池快照刷新。
- 项目状态、项目阶段、交付时间等项目级操作：继续保留即时快照刷新。
- 前端项目池分组、筛选、统计标签和工单弹框：不改交互和权限。
- 新工单或工单状态变化在下一次定时刷新后反映到项目池，默认最长约 5 分钟。

## 6. 配置

```text
COMPANYPLAN_PROJECT_POOL_SNAPSHOT_SYNC_INTERVAL_MINUTES=5
```

设置为 `0` 时关闭定时任务；默认值为 `5`。关闭后仍可通过已有项目池重建接口或服务端脚本手动刷新。

## 7. 验收标准

1. 工单创建、改派、状态修改接口不再等待项目池快照刷新。
2. 定时任务能刷新项目/版本的逾期、未完成和目前环节统计。
3. 定时任务能更新数据库快照并清理/重建 Redis 缓存。
4. “工单逾期”只统计超过 `due_at` 且未完成的工单。
5. 策划分组、环节分组和项目版本展示不受影响。
6. 定时任务失败不会导致后端进程退出。
